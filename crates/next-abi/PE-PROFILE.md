# NT-X64 development PE profile

`pe::PeImage` implements bounded parsing, loading and original shim import
resolution for PE32+ AMD64 console executables. This is an explicitly limited
NT-X64 compatibility profile; it is not a complete Windows runtime or a claim
that ordinary Windows applications work. No Microsoft DLL or Windows kernel
code is included. The independent fixtures contain original assembly and PE
metadata generated by the project's own packer.

The preferred image base is `native::IMAGE_BASE`; relocatable images are not
supported. Images reserve the final 16 KiB of the 256 KiB user executable window
for the runtime's original API shim. The parser supports at most 16 sections,
4 KiB section alignment, 512-byte file alignment, a single-page header, 64 KiB
stack reservation, and a 1 MiB bounded file. It checks DOS/NT/COFF/optional header
boundaries, machine and PE32+ type, section/file disjointness, image geometry,
readable sections, W^X, and a file-backed executable entry. Header pages are
read-only and non-executable; gaps, BSS and the reserved shim area are zeroed.

The only supported imported DLL is `kernel32.dll` (ASCII case-insensitive name),
with exact case-sensitive symbols `GetStdHandle`, `WriteFile`, and `ExitProcess`.
The allowlist maps to the project's own shim; no filesystem or external DLL
lookup occurs. Import descriptors, hint/name records, terminated lookup/IAT
arrays, complete file backing, duplicate symbols, and every RVA are validated
before process creation. The IAT must lie in writable non-executable data, use a
separate lookup table, and initially match its unbound lookup entries. Ordinal,
forwarded, delay, prebound, unknown DLL and unknown symbol imports are rejected.

DLL images, PE32, another machine type, ASLR/relocations, TLS, exceptions/unwind,
CLR, certificates, debug/resources/export/bound/delay directory features and
other unsupported data directories fail explicitly. A successfully parsed
image is not a signature, executable-capability grant, complete dependency
resolution, or a promise that the imported function semantics cover Win32.

Public loading methods are `entry`, `page_flags`, `copy_into`, `sections`, and
`imports`; each import exposes its IAT RVA, DLL/name and closed `ImportSymbol`.
The runtime patches the validated IAT and maps its dedicated RX shim separately.
The imported Win64 function calling convention, syscall/profile gates, checked
user-buffer operations and process containment belong to the runtime.

Six allocation-free ABI unit tests cover geometry, mapping, zero filling,
closed imports, rejected features, hostile RVAs/thunks and mutation safety.
The host profile harness also validates both actual generated original `.exe`
fixtures alongside independent Linux and native ELF profiles.
