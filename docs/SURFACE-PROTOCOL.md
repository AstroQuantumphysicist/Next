# Native surface protocol foundation

The new unexported `next-abi/src/surface.rs` and `prism/src/surface_state.rs` propose a bounded native presentation contract. Standalone host checks validate structure and configure/ack ownership/order. These files are newer than the immutable eighth image and do not establish a running display server, client IPC integration, memory isolation, GPU synchronization or a user compositor.

Version 1 messages contain an exact 80-byte little-endian header followed by zero to eight 16-byte pixel-coordinate damage rectangles. The magic is `NXSF`, version is 1 and header length is 80. Header offsets are: role at 8, pixel format at 9, damage count at 10, reserved zero at 11, flags at 12; surface/configure/frame generations at 16/24/32; buffer capability handle at 40; logical width/height at 48/52; pixel width/height at 56/60; 16.16 scale at 64; stride bytes at 68; exact buffer byte length at 72. Only unprivileged toplevel role 0 is accepted. Pixel formats are RGBX=0 and BGRX=1. The only flag is PRIVATE_CONTENT=1; it requests privacy treatment and never authorizes access or capture. Lock/system/modal roles need a separate authorized contract.

Each extent is 1–8192, scale is 1–4 inclusive, and pixel extent must equal the ceiling of logical extent times scale. Stride is a multiple of four and at least pixel width times four. Buffer length must equal stride times pixel height and be at most 64 MiB. Generations and handle are nonzero. Damage rectangles have nonzero sizes and checked ends within pixel bounds; an empty list declares no changed regions. Unknown fields, excess/trailing bytes, bad formats and overflow are rejected. Encoding validates in scratch before modifying the supplied output.

The structural descriptor is not a capability grant. The receiver must independently resolve the buffer handle with READ authority, enforce broker-owned client identity and surface ownership, validate mapped bytes and keep the resource alive until copying/presentation completes. Client-provided numeric identifiers must never stand in for authenticated channel or buffer-broker metadata. Arbitrary process memory must not be read through the descriptor.

The independent `SurfaceState` model accepts identities supplied by an authenticated adapter. Server-issued configure generations increase without wrap; a new configure supersedes an older pending configure. Only the latest pending generation may be acknowledged by its owner. Frames require that acknowledgment, exact configured geometry, the owning broker identity, the correct surface generation and a strictly increasing frame generation. Invalid transitions leave state unchanged. A new pending configuration blocks submission until acknowledged; how a real compositor continues displaying the prior retained frame remains an integration decision.

Host tests cover every truncated message length, trailing bytes, fractional geometry, privileged roles/flags, zero handles/generations, extreme extents/stride/length/damage, unchanged outputs on failed encode, hostile owner/buffer-owner changes, old configure acknowledgments, frame replay and generation exhaustion. Buffer pinning/copy lifetimes, close/revoke races, backpressure, client crash teardown and actual frame presentation still require the capability-backed receiver and guest proof. No complete §13 acceptance is implied.

## Tenth-source syscall contract (guest proof pending)

The protocol and independent state model are now exported without adding a Prism dependency. The 64-byte read-only `NXSC` configure record contains magic/version/header-size at 0/4/6, zero reserved bytes 8–15, surface/configure generations at 16/24, logical extent at 32/36, pixel extent at 40/44, scale at 48, and zero reserved bytes 52–63. Decode requires exact length, nonzero generations and the same bounded fractional geometry as frames. Retrieval leaves the pending configure unacknowledged.

| Native syscall | Registers | Result and authority |
|---|---|---|
| 38 SurfaceCreate | RDI width, RSI height, RDX rights | Positive surface handle; rights subset READ/WRITE/DUPLICATE = `0x0B`. No implicit GUI permission, system role, WAIT or transfer grant. |
| 39 SurfaceConfigure | RDI surface cap, RSI output, RDX capacity | Exactly 64 copied bytes after independent READ/full-output validation; short/bad output must preserve state and avoid partial writes. |
| 40 SurfaceAcknowledge | RDI surface cap, RSI surface generation, RDX configure generation | Zero on exact latest configure acknowledgment; WRITE required. Stale identities must not change state. |
| 41 SurfaceBufferImport | RDI input, RSI length, RDX rights | Positive immutable copied-buffer handle; nonempty bytes up to 64 KiB, rights subset READ/DUPLICATE = `0x09`. |
| 42 SurfacePublish | RDI surface cap, RSI frame descriptor, RDX descriptor length | Zero on queue acceptance; independently resolve surface WRITE and buffer READ, authenticated owner, generations, exact configured geometry and copied byte bounds. Acceptance is not scanout acknowledgment. |

The native resource profile is stricter than the wire ceiling: two global surfaces/four buffers, at most one surface/two buffers per owner and 64 KiB per buffer. Native transfer is unsupported. Duplication retains independently attenuated rights and the resource lifetime. The numerical masks use the actual shared ABI: DUPLICATE is bit 3 (`8`), TRANSFER bit 4 (`16`); these masks do not permit transfer.

The SDK offers borrowed `Surface`/`SurfaceBuffer` tokens and validates local lengths/rights before dispatch. SurfaceBuffer records its known imported size; publication overwrites the wire handle with that token and verifies descriptor length before calling the gate. Copying a Rust wrapper neither duplicates authority nor keeps a closed handle valid. The capability-backed receiver, original app fixture and trusted Prism consumer are being integrated separately; exported helpers and host tests are not evidence that a surface was shown in a guest.

## Independent source-stage rendering gate

`bash tools/test-client-surface-layout.sh` compiles the current Prism source into a host renderer and audits 72 resolution/format/theme/accent combinations: 640×480, 1280×800 and 1920×1080; RGB/BGR; Light/Dark/High Contrast; four accents. It submits two copied previews with exact 64-byte package captions and maximal PID, checks framebuffer guards/stride padding, and detects primary-caption pixels outside each trusted preview card. This host tool does not run a guest or attribute newer source to an immutable image.

The first actual run found caption escape on all 144 cards: wrapping 28 bytes ignores proportional glyph widths (`m` repeated 28 times is 364 pixels versus a 268-pixel caption area). The raw observation is retained in `work/client-surface-layout-before-fix.txt`; the UI owner is correcting pixel-width wrapping and dynamic caption/PID offsets. Exact public identity must remain visible rather than being silently truncated. Passing body-text contrast alone cannot establish that requirement.

Runtime source review confirms independent READ/WRITE capability resolution, signed principal ceiling enforcement at capability insertion, exact bounded configure copyout, immutable buffer import and explicit NotSupported for private-content presentation before capture/redaction exists. These source observations still need actual guest denial/lifetime/publication proof. Preview input must not reach trusted controls hidden below a visible client card; secure file-consent layers must remain above client pixels. Native clients currently have copied previews rather than full keyboard/pointer GUI input delivery.

The owning UI agent corrected the source-stage findings: captions now wrap by measured glyph advances; header height follows all label/PID/role lines, and a 64-byte PID writer preserves the maximal PID. Independent rerun passed all 72 combinations with zero overflowing cards; `work/client-surface-layout-after-fix.txt` retains the result. Preview pointer interception now precedes underlying editor/window actions while trusted modal layers, Home and the taskbar retain priority; a real overlapping dirty-editor close-hit regression covers the earlier click-through risk. These fixes and host results apply to tenth source, not the older eighth/ninth guest images.
