# Bounded trusted shell semantics

Source13 adds a host-tested semantic projection of the active trusted Prism context. It is not included in the finalized Source10 image or Source11/12 compiled snapshots. The exact Source13 image (`75b7eee4a19b`, compiled201-file `e40e61`) passed the actual119-assertion F9 guest gate; the diagnostic is local development observation. No requirement status is promoted by this document.

The caller supplies snapshot storage. The kernel uses a static snapshot rather than putting its 48-node aggregate on the kernel stack. A projection starts with `complete=false`; only successful observation marks it complete. Every node has a context-scoped identity, an existing parent, a bounded UTF-8 name, role and state. One enabled visible node may be focused. Names are limited to 128 bytes and values to 192 bytes. Geometry is optional descriptive metadata; it does not authorize a click or grant access to an application.

A semantic generation advances when observed content, context, hierarchy, state or available geometry changes. Ordinary redraws preserve it. The observer queues at most eight typed events and reports Reset when overflowing. The kernel records those events after successful framebuffer presentation with the actual completed frame generation. Consumers must retrieve a complete snapshot after Reset rather than infer a missing event history. A projection error is explicit; partial trees must not be presented as complete observations.

The projection selects one active context, including trusted modal prompts before underlying windows. It includes shell-owned labels, roles, enabled/visible/focused/selected/checked/busy states and available control geometry. Native client pixel content exposes a trusted package caption and an explicit status explaining that it has no accessibility tree. Pixel publication does not supply application control semantics.

## Development diagnostic

The development F9 readback observes the last completed static snapshot without changing the active UI context or regenerating a tree. Serial command entry opens Terminal, so a regular `a11y` shell command cannot by itself inspect the previous Settings/modal context. This hotkey is a local development aid, not an assistive-technology transport.

A BEGIN record contains actual frame, semantic generation, context, token, node count and focused local identity. Each NODE record contains local identity, parent, role, state, optional bounds and hex UTF-8 name. END repeats the actual frame/generation/count. Values are intentionally omitted to avoid logging editable documents, commands or prompt contents. Plain F9 is consumed before Shell dispatch, including under a modal; repeat/chord/extended/Pause bytes do not trigger the diagnostic. Names can still include file paths; diagnostics must remain explicit local observations and must not become automatic support exports.

`tools/accessibility_readback.py` implements strict decoding of this record format. Its host tests reject incomplete or nested transactions, mismatched identities/counts, backwards frame/generation, dangling parents, duplicate identity/focus, malformed names and unknown records. They prove decoder behavior, not a guest-produced dump. The kernel readback hook is present in Source13. `tools/accessibility_smoke.py` passed an actual source-bound119-assertion qemu64 guest run. Eight complete dumps show readonly portal request identity/modal precedence, Settings focus101→102, unchanged semantics on repeated F9, Files selected rows, query focus10→11, and cancellation back to Files. Exposed geometry was checked against framebuffer dimensions, captures retained, source/image bindings unchanged, and UART metrics report accepted=transmitted210428/dropped0/pending0 with2419bounded stalls. This is not a universal lossless UART claim. Its initial inherited portal navigation wait consumed a pending initial row rather than the actual Down response; the failed wrong-file fixture attempt is retained separately. The successful retry uses actual action marks/full-line/completed-frame barriers without changing the image.

## Acceptance gates

An actual guest gate must bind the prepared image and retained compiled source manifest; exercise real keyboard/pointer actions; retrieve complete post-present records; compare names/roles/focus and selected rows with the visible active context; and check exposed geometry against screenshot dimensions and known trusted controls. It must verify trusted modal precedence and that underlying windows disappear from the active semantic context, with cancellation returning to the actual previous context. Redraws without semantic changes must preserve generation. Focus/context changes must advance it and match completed frames. Any unavailable snapshot or missing required control fails the applicable gate.

This foundation leaves substantial spec sections 12.3 and 23.2 unfinished: screen reader, speech, braille, magnifier, alternative input, accessible login/installer/recovery, external accessibility API, native/foreign application trees, large text/layout adaptation, caret tracking, reduced motion/transparency, sticky/filter/toggle keys, configurable repeat and pointer settings. Current ASCII raster typography does not establish shaping, bidi, localization or Unicode composition. High-contrast rendering and keyboard-focused development tests are scoped evidence rather than certification of accessibility or Next 1.0 readiness.
