# Native resize validation scope

Source15 adds a trusted user resize gesture for an ordinary capability-owned native window. The app cannot choose a new configure generation, resize another surface or acquire focus through configure/ack/publication. The current profile keeps scale at 1, bounds each copied pixel buffer to 64 KiB and uses the existing surface capability syscalls.

The original signed `client-reconfigure-probe` creates a 64×48 BGRX checkerboard with READ, WRITE and WAIT surface rights. It owns no Launcher, file namespace or privileged window role. On a trusted reconfiguration reset it retrieves and acknowledges the current descriptor through `SurfaceSession`, then imports and publishes a new full-damage checkerboard with a strictly increasing frame generation. It accepts dynamic bounded geometry rather than assuming a fixed resize target. Raw syscall checks exercise stale configure/frame metadata, an old-size buffer and a closed buffer handle; the latter two checks reach the kernel rather than stopping at SDK length validation. Reconfiguration does not restore input focus. A fresh real content gesture and `q` are required for success exit52.

`tools/native_resize_smoke.py` requires explicit retained source-manifest and image SHA256 values. Its geometry helper compiles the retained Prism source and verifies every retained Prism source/asset hash. The guest gate uses QMP pointer gestures on the actual public resize grip, joins exact surface identity and old/new configure generations with the trusted transaction marker, and waits for completed framebuffer-copy markers. Literal checkerboard pixels are compared across the complete actual content rectangle, including nonintegral nearest-neighbor scaling. It performs grow and shrink gestures one at a time, checks no automatic focus acquisition, observes exit52 and exact-generation teardown, then captures the actual guest Home, Files and Settings screens and restores Terminal before the inherited baseline.

Host preflight currently passes the transaction/configuration parsers, corrupted-edge and invalid-crop refusal, source-bound initial/grow/shrink public geometry, and signed application digest/identity checks. These results do not establish an actual Source15 guest pass. The parent full-suite/build result and frozen image/source hashes must be recorded separately; the validator refuses mismatched hashes. Guest evidence will be retained under its explicit output directory after the image is frozen and the VM is handed over.

This gate covers a trusted kernel software compositor and sequential explicit user resize gestures. It does not establish an isolated compositor, GPU synchronization, private capture/redaction, physical key-release delivery, arbitrary concurrent configure races, power-loss behavior or completion of the full NEXT specification. The app can fail if a future trusted caller reconfigures between successful acknowledgment and publication; the current gesture path blocks another resize until the new acknowledged full frame is available, and the validator waits for that completed frame before its next gesture.
