# Bounded authenticated service configuration

The bf5faba56301 development milestone delivers `config/services.bin` as a member of the exact running signed `nextd` application bundle. The kernel re-verifies that bundle and binds its package/executable digests to PID1's immutable principal before returning configuration. CRC alone is not authentication. Each worker launch checks its independently verified signed package ID and executable digest, then attenuates configured permissions/capability rights before creating the process.

The little-endian format has a 32-byte header and 256-byte records, with one to eight declared services and an exact maximum of 2080 bytes. Header magic is `NXSVC001`; version is 1, sizes/count/total are checked, and IEEE CRC32 covers exact bytes with offset 20–23 zeroed. Byte 24 is a nonzero active-service mask; unused bits and dependencies outside that mask reject. Bytes 25–31 are reserved zero. All declarations, including disabled ones, are checked for canonical names/paths, duplicate service names, missing/self dependencies and cycles.

Each record contains a zero-padded name (32 bytes), absolute `/system/` path (64 bytes), expected package ID (64 bytes), executable SHA256, wire capability and permission ceilings, dependency mask, maximum starts, start-window/backoff/maximum-backoff/health nanoseconds, and zero reserved fields. Unknown permission/right bits and ADMIN reject. Repeated package/path values may describe separate worker instances. The parser establishes structural validity; trusted delivery and exact signed worker binding provide authentication.

Native call 32 returns these bytes only to authenticated PID1. Its complete supplied output range must be valid; invalid/null/zero/oversized output returns InvalidArgument before lookup, a valid short buffer returns BufferTooSmall, and no error partially writes output. Spawn flag START_SERVICE=2 identifies the configured index in R9. Worker grants currently have capability ceiling 0x1b and permission grant 0, without inherited launcher authority.

Default active mask 1 keeps one supervised worker and leaves two console process slots. A separately signed mask 3 test configuration uses the same kernel and nextd executable payload and runs two workers concurrently. Guest evidence verifies primary readiness before dependent creation, dependent stop on primary failure before dependency recovery, distinct restart PIDs and both final workers alive with PID1. The alternate image is intentionally distinct and identified in the [report](evidence/milestones/bf5faba56301/service-pair/service-pair.json).

This is a bounded development service fixture. Global process/handle/memory limits are not independently configured per-service budgets. General service owners, user/session creation, persistent service settings, health APIs, complete system transitions, general crash recovery and SMP concurrency remain outstanding.
