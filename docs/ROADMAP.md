# Integration roadmap

Next now verifies signed development deployments, boots a separate kernel/init image, runs isolated bounded native programs with capabilities/IPC and timer preemption, contains child faults, writes a small COW store across VM reboots, performs DHCPv4 acquisition and ARP/ICMP/UDP/TCP and local DNS/cache probes plus AC97 DMA playback, renders five interactive development panels, and executes an original static Linux syscall fixture. These integrated portions do not close the full [Next 1.0 specification](NEXT-1.0-SPEC.md). The [status inventory](STATUS.md) retains the remaining acceptance work.

The gates below follow dependencies. Defined interfaces allow parallel implementation, but each gate needs its own complete acceptance evidence. No timeline, universal compatibility or perfection guarantee follows from this roadmap.

The next integration work with the strongest existing foundation is a complete capability VFS and complete Linux/POSIX file semantics beyond bounded native/Linux streams; general wait-many and cancellation beyond the new blocking events and channel wake/close/cancel behavior; and an isolated userspace Prism service using defined display/surface/input IPC. File APIs should preserve distinct native/POSIX/NT semantics, waits need adversarial lifecycle tests, and graphical service separation needs shared-memory lifetime rules rather than raw kernel pointers. These changes would support independent applications beyond the current console and test fixtures.

Resource bounds, security, ABI versioning, accessibility and failure behavior apply throughout. A later feature cannot conceal missing earlier invariants. An ELF parser, static compatibility fixture, screenshot, clean VM reboot or host crash model cannot replace the corresponding full end-to-end and hardware acceptance gate.
