# Independent implementation gates after the bounded runtime

Current source work includes shared-inode files, TLS, service supervision and an editor. Their acceptance must be recorded against a new validated image; existing milestone snapshots remain unchanged. The following gaps can be tackled independently of that work. They are bounded steps toward the specification, not substitutes for its final contracts.

| Work item | Concrete first implementation | Required acceptance | Remaining full-spec scope |
| --- | --- | --- | --- |
| Read-only filesystem verifier (§10.3) | Host CLI opens a disk read-only, identifies an explicitly supplied protected data extent, checks both superblocks/roots/all file CRCs and reports candidate generation and corruption without repair | Valid golden image, stale/torn superblock, bad root/content, truncated media, overlapping extent and unknown nonblank metadata; hash entire source before/after every run; no writes even on failure | Full NextFS trees/extents/snapshots, fsck repair/salvage, encryption and physical durability |
| Bounded DNS client (§11) | Original DNS query/response codec over the existing UDP path with exact transaction/question/source binding, label/compression bounds, CNAME depth budget and deadline | Host malformed compression cycles/offsets/truncation/count overflow; actual QEMU query against a loopback-only DNS fixture with A/NXDOMAIN/error/timeout cases | Resolver service/cache/negative TTL policy, IPv6, mDNS, DNS Settings and general network interoperability |
| Signed application identity (§8, §20) | Bind a verified package ID/version/content digest to launched process metadata and startup authority, independently of executable display name | Renamed executable retains authenticated identity; changed bytes/unsigned alias cannot acquire identity; launch permissions are attenuated by caller grants; process reuse clears identity | Principals/login, persistent consent/portals, runtime revocation, production repository and boot trust |
| User display surfaces (§13) | Capability-owned shared pixel buffer and explicit validated surface/input IPC between one native client and a bounded display broker | Buffer overflow/stride/format rejection, close/revoke during pending frame, client crash cleanup and broker restart preserving other clients; keyboard-only recovery | Isolated full compositor, GPU/fences/vblank, fonts/Unicode, accessibility and physical display qualification |
| Installer dry-run (§3, §10, §20) | Host-only GPT planning tool reads a scratch disk, validates headers/partition CRCs/bounds and prints an explicit proposed layout without writes | Corrupt primary/backup GPT, overlapping/out-of-range partitions, existing user volumes and unsuitable capacity; byte-for-byte unchanged disk on every failure/plan | Actual consented partition writes, accounts/encryption, production signed images, recovery and physical installation |
| ACPI topology foundation (§2, §5, §9) | Bounded read-only RSDP/XSDT/MADT parser with checksum/range/type validation and an explicit discovered CPU/APIC catalog | All truncations, checksum corruption, duplicate IDs, unknown records, address overflow and malformed lengths; guest discovery must not imply AP startup | APIC interrupt routing, SMP scheduling/shootdowns, NUMA, suspend/power and certified firmware |

The filesystem verifier and DNS codec build directly on working storage/network paths and have clear failure oracles. Application identity closes a real security gap between signed deployment bytes and per-process authority. Display surfaces are the prerequisite for moving Prism panels out of the kernel. GPT dry-run and ACPI parsing are useful safe foundations but cannot be reported as an installer or SMP support.

For every item, name the exact accepted profile, separate host model/parser coverage from actual guest workflows, and retain failures alongside later successful runs where possible. `python3 tools/spec_coverage.py` displays the complete pending/partial inventory and linked evidence; it does not assign completion from the presence of source files.
