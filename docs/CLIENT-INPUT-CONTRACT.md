# Next client input integration gate (planned)

Tenth-source native surfaces presently publish owned CPU-copy previews into the trusted desktop. Pointer interception prevents clicking the trusted window underneath; that does not deliver input to the native process. A client can create/ack/publish/close capabilities, but cannot yet interact as a general app window. No immutable milestone establishes that missing behavior.

The next meaningful step is one bounded client input stream paired with the existing surface capability. The trusted compositor chooses focus from an actual pointer/keyboard user gesture; create/publish must not steal it. The authoritative origin is the immutable surface owner and generation, not a client title, package string, PID argument or pixel content. A stale reused slot must never inherit focus or queued input. Close/process exit clears its queue and visible/focused state.

Route validated keyboard events and pointer coordinates only to the focused/targeted surface. Preserve the original timestamp, an increasing event sequence, surface generation and configure generation. Coordinates are relative to the current content extent and clipped/validated under that configuration. Unknown event kinds/reserved flags, unsupported key encodings, impossible button masks and stale configure events reject explicitly. Secure shortcuts remain in the trusted shell; a background surface must never see portal/password or unrelated terminal keystrokes.

A bounded queue needs a documented overflow policy that cannot leave keys/buttons logically held forever. If discrete input cannot be retained, emit an explicit reset/focus-loss state and clear held-key/button state; never silently drop only a release. Pointer motion may be coalesced only while preserving button/focus transitions and the last event's timestamp/coordinates. Reading an event requires independent surface-owner/capability rights, validates the complete output range and preserves the event on short/bad copyout. Poll/wait readiness must not consume an event; close/timeout/cancellation must preserve defined output behavior.

Trusted overlays retain input priority: file consent, destructive confirmation, notifications/Home/taskbar and reserved shortcuts act according to their actual z-order. Opening a modal temporarily suspends client focus and input; closing it restores only a still-live eligible surface under a documented policy. Native requests cannot directly set that trusted focus or impersonate a secure surface role. Visible client controls belong inside their content rectangle, while trusted caption/origin/close controls remain independently drawn.

Concrete guest acceptance requires an original signed app that receives real QMP keyboard and pointer input through its capability, changes owned pixels in response, publishes a new frame and is observed after completed presentation. Click one of two surfaces and prove only its owner receives keys; create/publish another surface without a gesture and prove focus stays put. Open a trusted portal and verify client input stops; cancel and verify the defined restoration. Short/invalid output must retain events; repeated reads must not duplicate consumed events. Kill the focused process, reuse its slot and prove stale focus/events/caps cannot affect the replacement. Queue exhaustion must reset held state and retain trusted-shell responsiveness. All fixtures, raw input/event/frame sequences, identities and screenshots must be tied to one frozen image.

These bounded proofs would establish client interaction foundations. They would not establish a userspace display server, full text-input/IME/accessibility protocol, arbitrary multiwindow app behavior, Wayland/Win32 GUI compatibility, GPU fences or physical latency certification.

## Exported eleventh-source ABI (runtime proof pending)

`next_abi::client_input` now defines an exact 64-byte `NXSI` version-1 record: magic/version/header length at 0/4/6, kind at 8, zero reserved bytes 10–15, surface/configure generation at 16/24, sequence at 32, timestamp nanoseconds at 40, and three payload words at 48/52/56 with zero reserved word at 60. Nonzero generations/sequences and exact record lengths are mandatory. Kind values are FocusGain=1, FocusLoss=2, Key=3, Pointer=4, Reset=5. Focus payloads are zero; Reset allows only nonzero overflow/focus-loss/close/reconfigure reason bits. Pointer coordinates are nonnegative and below 8192, with only the three known button bits; the receiver must additionally check the current configured extent.

Key codes are Character=0, Enter=1, Backspace=2, Tab=3, Escape=4, Up=5, Down=6, Left=7, Right=8 and Menu=9. Characters use a valid non-control Unicode scalar; named keys require scalar zero. Actions Press=1/Release=2/Repeat=3 have wire definitions, but the current PS/2 semantic input path actually supplies press actions. The codec does not manufacture physical release/repeat events or establish multilingual rendering.

Native syscall 43 `SurfaceInputRead` uses RDI surface capability, RSI output, RDX capacity; it requires READ and returns exactly 64 bytes for one consumed record. The runtime/broker must preserve the queued record on short/bad output, enforce authenticated surface ownership and return WouldBlock for an empty queue. SDK `Surface::read_input()` supplies the exact output and decodes structure, while `wait_input(Wait)`/`poll_input()` use level-readable ObjectWait with independent WAIT authority and no event consumption. The surface rights mask is now `0x2B` = READ|WRITE|DUPLICATE|WAIT; it still excludes TRANSFER. No client syscall sets trusted focus. Queue, focus routing and guest fixture integration are separately owned and remain pending proof.

Source12 negotiated close contract (host codec/SDK proof; guest proof pending)

The original NXSI v1 grammar remains strict. A client opts into cooperative close requests for an exact configuration through SurfaceAcknowledge40: RDI surface capability, RSI surface generation, RDX configuration generation, R10 feature bit0 (`FEATURE_CLOSE_REQUEST=1`), R8/R9 zero. Unknown feature bits must fail before acknowledging or changing negotiation. Reconfiguration invalidates negotiation, pending close identity and old queue/tickets together; the client must opt in again for the new configuration.

SurfaceInputRead43 keeps R10=0 as the v1 request. R10=2 explicitly requests NXSI v2, still exactly64 bytes. Other versions fail before queue access. V2 uses the same full surface/configuration/sequence/timestamp tags and original input payload validation. Kind6 is CloseRequested: an opaque nonzero u64 ticket occupies bytes48..56 and bytes56..64 remain zero. Reading a close request through v1 must return NotSupported without consuming it. Reading through v2 preserves bad-copyout/short-buffer failure atomicity. Choosing a record format never grants permission or focus.

SurfaceCloseReply44 requires WRITE and takes RDI surface capability, RSI surface generation, RDX configuration generation, R10 ticket, R8 request sequence and R9 response. Responses are Refused1 or WillClose2; zero and unknown values fail. The owner broker must match every field against one exact live pending request, reject stale/repeated/wrong-owner replies, and revoke the request on reset, overflow, reconfigure, teardown or its independently enforced deadline. Wire data cannot extend that deadline.

WillClose is advisory. It does not destroy a surface, close capabilities, terminate a process or make pixels disappear. Completion requires actual authorized lifetime teardown. A timeout may produce an Unresponsive state; it cannot silently kill the client. Any Force Quit action needs its own trusted confirmation and process authority. The SDK exposes `acknowledge_close_events`, `read_input_v2` and `reply_close`; old clients can continue using strict v1 and ordinary acknowledgement.

## Source14 client configuration helper

`next_user::sdk::SurfaceSession` is a client-side state helper, not a resize or focus API. It borrows an existing unpublished surface token and requires one exclusive publisher. Aliased sessions or manual publication need independent frame-counter coordination; copying a token supplies none. `SurfaceLayout` contains the actual server configure, packed stride and byte length checked against the native 64KiB buffer budget.

`refresh()` retrieves the latest descriptor. Public `acknowledge(configure)` also compares every field against the current read-only server descriptor before acknowledging: the kernel Ack checks generations, so merely accepting structurally valid caller geometry could otherwise poison local state. Foreign/stale configurations and equal-generation altered geometry fail. An exact active descriptor is repeatable without issuing an illegal second Ack. Configuration is committed locally only after successful Ack, and the explicit requested close opt-in is reapplied for each new configuration. A racing reconfiguration may cause an error and requires retry; it never commits an unacknowledged candidate.

`publish_full` supplies full damage, including the first frame after configuration, and preserves a monotonically increasing frame identity across reconfiguration. Its counter advances on accepted queue submission, not actual scanout. WouldBlock, malformed geometry, wrong buffer size, terminal native errors and counter exhaustion leave that counter unchanged. Imported resources and closing their capabilities remain the caller's responsibility; this helper has no implicit ownership or Drop behavior.

Four host regression groups exercise forged first-descriptor rejection, failed reads/Ack/publication, stale identity, bounded fractional-scale layouts and overflow. These are Source14 source/host evidence. The staged reconfigure-aware fixture is not enrolled in that image, and a trusted live resize gesture plus configure-bound actual guest republishing remains a separate acceptance gate. This helper supplies no application-requested resize, focus restoration, physical key-state or general window-manager certification.
