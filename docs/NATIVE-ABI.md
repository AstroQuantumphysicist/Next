# Native development ABI

This is the implemented experimental x86-64 interface, not the frozen Next 1.0 SDK. The [ABI crate](../crates/next-abi/README.md) documents boot/executable layouts; [architecture](ARCHITECTURE.md) explains isolation and missing product interfaces.

Native applications enter `int 0x80` with the call number in RAX and arguments in RDI, RSI, RDX, R10, R8, R9. RAX returns a nonnegative value or a signed negative `next_abi::Status`. Linux personality entry and numbering are separate. User pointers are checked for mapped bounds and required permissions before access.

| Number | Call | Bounded behavior |
| --- | --- | --- |
| 0 | Exit | Retains signed process result for authorized waits |
| 1 | LogWrite | Authorized bounded UTF-8 logging |
| 2–3 | HandleClose, HandleDuplicate | Generation checks, reference cleanup, rights attenuation |
| 4 | ObjectWait | Process/event poll or bounded blocking wait; validated pointer receives an i64 result |
| 5–6 | ChannelSend, ChannelReceive | Framed bounded messages and attenuated moved handles |
| 7–8 | MemoryMap, MemoryUnmap | Zeroed private anonymous mappings, 64-page arena, W^X |
| 9 | ProcessSpawn | Launcher capability, explicit native/Linux executable profile |
| 10–11 | ThreadYield, ClockRead | Single-CPU scheduling and PIT monotonic nanoseconds |
| 12–15 | ChannelCreate, ProcessKill, ThreadSleep, SystemReady | Capability/deadline/supervisor checks |
| 16 | FileOpen | Launcher, path pointer/length, create/truncate flags, requested rights |
| 17 | FileRead | READ capability, validated output buffer, returns byte count |
| 18 | FileWrite | WRITE capability, bounded input, atomic COW replacement |
| 19 | FileSeek | Signed offset, origin 0/1/2, shared stream offset |
| 20 | FileStat | READ capability; two u64 values: length, offset |

`FileOpen` arguments are launcher, path pointer, path length, flags, rights. Flags bit 0 creates an absent file and bit 1 truncates; either requires WRITE. The `/native/` namespace uses canonical ASCII paths of at most 31 bytes. Requested rights may include READ (1), WRITE (2), DUPLICATE (8) and TRANSFER (16), with unknown bits rejected. Current source has eight generation-checked open descriptions: independent opens share inode content with separate offsets, while duplicate and IPC-moved references share one description and offset. Console rename/delete integrates with inode identity; unlink/destination replacement detaches the old inode while existing references retain its bytes until final close. Detached writes update retained memory rather than recreating a deleted path. The f42210 positive guest scenario tests these changes; milestone 418ea still used exclusive opens. Files are at most 4096 bytes and disk errors may make the underlying writer unusable until remount. This does not implement general mounted namespaces, credentials, full POSIX lifetime/concurrency or asynchronous I/O; Linux descriptors are a separate bounded adapter.

`EventCreate` flag bit 0 selects manual reset and bit 1 sets the initial signal. Rights may include DUPLICATE (8), TRANSFER (16), WAIT (32) and SIGNAL (64). Sixteen event objects are available. Manual-reset polling preserves the signal; successful auto-reset polling consumes it. Wait validates its eight-byte output before consumption. ObjectWait arguments are handle, eight-byte result pointer, flags and absolute monotonic deadline. Flags 0 polls and returns WouldBlock when unsignaled; flags 1 parks the task until completion or timeout. Unknown flag bits reject. Deadline 0 means no timeout; an expired nonzero deadline returns TimedOut before signal consumption. Authority and writable output are validated before parking and again before completion. Manual-reset signals remain set; one successful auto-reset waiter consumes the signal. The single-CPU scheduler tracks one pending wait per process, preserves output on timeout, and clears pending state during process teardown. Process results remain retained across repeated/duplicated waits. This is not atomic wait-many, a general cancellation-token interface, blocking channel I/O or an SMP wake protocol.

MemoryMap currently requires zero address/reserved arguments and accepts a length plus read/write/execute protection flags. It uses the same bounded allocator as Linux private-anonymous mappings; executable writable pages are rejected. MemoryUnmap accepts a page-aligned address and bounded length. These calls do not create general VMOs, shared mappings or demand paging.

Both tested CPU profiles preserve integer and 512-byte FXSAVE state. Unsupported unsaved user controls are disabled/reset. The single-CPU kernel uses a guarded 64 KiB privilege-entry stack for syscall and interrupt entry, including nested bounded storage work. Explicit FS/GS process state is preserved; general per-thread kernel stacks, SMP, language TLS/relocations and extended-state support remain separate work.

`ClockRealtime` validates its complete 16-byte writable output before querying the immutable q35 RTC/PIT anchor. Unavailable RTC returns NotSupported; overflow/regression returns IoError. UTC is normalized and distinct from uptime. This does not set wall time, implement timezone/NTP or support arbitrary RTC platforms.

`PortalRequestOpen` takes requested access in RDI and absolute monotonic deadline in RSI, strictly future and at most 30 seconds away. The signed principal independently bounds the requested authority; a manifest request is not consent. It returns a positive identity/lifetime-bound request ID. Trusted chooser approval selects an existing /native/ file and holds its inode. `PortalPoll` takes that ID in RDI, reserves capability capacity before consuming approval, returns a positive file handle with exactly granted READ or READ|WRITE authority, and cannot mint a duplicate grant. Pending returns WouldBlock; denial AccessDenied; expiry TimedOut; acknowledged/stale requests InvalidHandle. `PortalCancel` takes the ID, cancels a pending/approved request and releases held resources. Process exit tears down requests/held inodes. The chooser and adapter currently run in the kernel; no persistent consent, file creation, general permission broker or SMP race contract is implied.

Source11 adds an explicit trusted development-console `runfiles PATH` grant for native applications. Its startup `launcher` field carries a distinct FileNamespace object with READ|WRITE, not launcher EXECUTE authority. FileOpen and namespace rename/unlink recognize that role and require the matching signed declaration, independent execution permission grant and capability ceiling; writes require both READ and WRITE. The initial namespace object cannot be duplicated or transferred. It cannot authorize Spawn or SystemReady, which still require the Launcher role and EXECUTE; IPC also rejects transferring either role. Ordinary `run` adds no namespace grant, compatibility/service/root launch paths cannot use this option, and path access remains restricted to `/native/`. These are Source11 code boundaries awaiting their own guest proof, not capabilities of the frozen tenth image. This development command is not a production consent or persistent permission service.

The bf5faba56301 development image validates this bounded service contract: `ServiceConfiguration` is assigned number 32. RDI is an output pointer and RSI capacity in 1..2080. Only PID1 with its actual signed-principal-bound service configuration may retrieve it. Success copies the exact authenticated bytes and returns their positive length; insufficient valid capacity returns BufferTooSmall with no partial write; null, zero, oversized or an invalid full capacity range returns InvalidArgument before manifest lookup, unauthorized callers return AccessDenied. There is no size-query special case. Structural service parsing alone does not authenticate configuration or grant authority. The config is a signed member of the exact running supervisor bundle; independently signed worker identities and configured capability ceilings are checked before launch. Spawn flag START_SERVICE=2 uses R9 as the configured service index and is restricted to authenticated PID1. Services receive a scoped endpoint/log grant without inherited launcher authority. Default active mask1 and a separately signed mask3 configuration have scoped guest proof; general per-service budgets and a full service manager remain absent.

Seventh-wave validated development guest profile, outside the immutable bf5faba56301 milestone: DatagramCreate/Send/Receive are assigned33–35. The SDK exposes bounded connected UDP helpers; queued datagrams and authenticated NETWORK policy require separate live integration proof. This source does not establish application sockets in the sixth milestone. [UDP-PROFILE.md](UDP-PROFILE.md) records the exact bounded authority, peer, queue and copyout contracts. Seventh scoped milestone validation passes; eighth writable/blocking readiness extensions remain separately pending guest proof.

Eighth-wave source extension, outside the recorded seventh image: ObjectWait's bit 1 selects writable Datagram readiness; bit 0 retains blocking mode. Flags 2 poll writable, flags 3 block writable, and flags 0/1 retain readable or existing object waits. Event/Process handles reject the writable selector; unknown bits reject. Valid handle/WAIT/NETWORK authority and complete writable output are checked before park and again on wake. Success writes signed zero and returns zero without consuming packets; timeout preserves output/queues. Driver or lease failure terminates blocked socket waits instead of treating stale queue capacity as network readiness. SDK Datagram::wait_readable and wait_writable take Poll/Block/Until, with poll_readable/poll_writable conveniences. Native guest proof for the eighth extension remains pending.
