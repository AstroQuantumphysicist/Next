# Prism Files nested directory interaction slice

This Source16 slice adds bounded nested-directory navigation and actions to Prism Files. It sits above the trusted Store adapter in `next_fs::journal::directories`; the model grants no storage authority and never synthesizes a row from a path prefix.

The live Prism Files view requests `/native` when opened. A trusted adapter returns the current directory identity and generation plus immediate children from the Store. Directory rows navigate, file rows return their exact listed paths to the existing file-opening flow, and Up stops at `/native`. The address field accepts only the existing bounded absolute path grammar; the backend remains authoritative about whether every ancestor is an explicit directory. File create, rename/move, copy, and trash actions continue through the existing snapshot-bound file dialogs; successful changes refresh the visible directory listing.

New folder, move folder, and remove folder actions all start unapproved. New folder requires a direct child path. Move can change a folder name or parent, but the backend must validate the exact source identity, destination parent identity, ancestry, global generation, and empty-directory rule in one serialized transaction. Remove requires explicit approval and applies only to the selected directory. The UI adapter must compare the selected directory's persistent ID before calling `rmdir`; a nonempty directory produces `NotEmpty` and stays visible. Moving a folder into itself or its descendants is rejected in the model and again by the backend.

A mutation does not optimistically edit visible rows. The adapter commits through the Store, obtains a fresh listing for the displayed source parent, and completes the matching request. The model accepts only a newer generation, the expected directory identity, and the operation-specific presence/absence checks. It preserves the exact directory ID on move. Failed operations retain the current listing and user input; a stale callback cannot replace the current view.

The Explorer renderer uses a grouped toolbar, location bar, distinct file/folder rows, empty-folder hint, and cancel-first dialogs within the existing Prism window bounds. The same bounded row model and action mapping drive keyboard, pointer, and keyboard-focus navigation. The live filesystem currently has a bounded eight-slot Store and an ASCII path profile. Directory records use those same slots, so folders reduce file/trash capacity. This slice does not provide nonempty-directory rename, recursive delete, multi-select, a folder tree, tabs, dual pane, Unicode names, mount browsing, drag-and-drop, or guest/QEMU proof.

Unit coverage in `crates/prism/src/files_directory.rs` checks authoritative navigation and file activation, missing paths without fabricated directories, cancel-first creation and conflict retry, empty-only move/remove failure behavior, cross-parent identity preservation, cycle rejection, stale and malformed listing rejection, and refreshed-list requirements. Shell tests cover the Files controls and modal input priority. The focused command is `cargo test --locked --offline -p prism --lib files_directory`.
