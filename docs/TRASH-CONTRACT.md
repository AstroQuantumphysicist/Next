# Bounded Trash integration contract

The bounded Store two-operation transaction underlies the implemented coherent Trash adapter and trusted kernel Files controls. It stages one or two ordered Create/Replace/Rename/Remove operations, checks the expected global generation, validates canonical names/capacity/lengths and existing payload checksums, then uses one existing COW commit. No intermediate namespace is published. Its authority comes from the trusted caller, not metadata or checksums. The immutable Source11 checkpoint (`8236ffef6154`, compiled188-file `c2b527`) includes an actual two-boot117-check-per-phase Trash gate; this does not establish a full Trash service.

The implemented development profile holds at most two deleted native files, each up to the existing 4 KiB file limit, with one reserved metadata object per file. Native source paths remain confined to `/native/`; generated data and metadata keys live under a trusted reserved `/trash/` prefix and are not opened through application namespace calls. Keys must fit the 31-byte journal limit. The current eight-object store makes free-space checks essential: moving a file does not need a new data slot, but creating its metadata does need one. Full Trash must return a clear capacity failure without deleting an existing item or falling back to permanent deletion.

Move-to-Trash uses exactly one transaction: non-replacing Rename from the authorized current source to its generated reserved data key, then Create of bounded canonical metadata. Restore uses exactly one transaction: non-replacing Rename back to an independently authorized destination, then Remove of that exact metadata key. A collision must leave the Trash record and destination unchanged; the default is cancel or choose another name. Permanent removal of a Trash item uses Remove data plus Remove metadata in one transaction and needs explicit destructive confirmation. Generating keys from the next committed generation requires checked arithmetic and collision validation; persistent IDs must not wrap or be reissued.

Metadata identifies a version, item ID, exact original path bytes, expected size/checksum, and the single supported profile owner. Unknown versions, reserved bits, noncanonical paths, excessive lengths, missing paired objects, mismatched payload fingerprints and trailing bytes must reject without repair or silent overwrite. CRC detects corruption, not authenticity. The trusted adapter must independently bind ownership to the session/profile policy; app-supplied user IDs or metadata labels do not grant access. Current single-development-session ownership must not be presented as multi-user Trash isolation.

## Open-inode coherence

The kernel routes mutations through the coherent `helix_core::file::Files` adapter rather than invoking the raw Store transaction behind its cache. An already-open source inode would retain the old linked path, a cached metadata object could remain stale, and a later descriptor write might recreate the wrong name. Calling ordinary Files rename/remove in sequence is also unsuitable: two backend commits expose an intermediate state.

The implemented adapter stages one bounded coherent transaction under the existing file/cache lock. Before I/O, validate the expected disk generation and every source/destination/cache transition without mutating live inodes. The backend executes one Store transaction. Only after its successful receipt does the adapter apply all staged cache changes together. Failure preserves cache names/bytes/offsets and obeys the backend's indeterminate/read-only state; it must not retry or publish success after uncertain commit. Existing open descriptions retain their inode and shared offset. A moved open inode follows its new link; a permanently unlinked open inode stays anonymous until last close. Restoring the same item must preserve that inode relationship where it remains live. The supported behavior must be tested rather than achieved by flushing all open handles.

## Concrete acceptance tests

- Move an actually open native file to Trash, read/write through its retained descriptor, and confirm the reserved linked data object changes without recreating the original path. Duplicate descriptions preserve shared offsets.
- Restore while the descriptor remains open, verify one committed generation and correct new name/content, then close all references and reopen. A conflicting destination preserves both files and the exact Trash record.
- Fill all eight objects or both Trash slots; move must fail before any write and leave source bytes, opened inode, metadata and generation unchanged.
- Inject failure/torn writes at every operation/flush boundary of move, restore and permanent removal. Independent remount must expose the complete old or complete new pair; in-memory cache must never advertise an unconfirmed state.
- Corrupt metadata or paired content, alter owner identity, use stale item/generation, or propose a path outside `/native/`; reject without writes and keep the original objects inspectable through explicit trusted recovery.
- Actual QMP keyboard/pointer controls must show Move to Trash, Restore and permanent-delete confirmation distinctly. Default cancellation must preserve files. Reboot the same disposable data image and restore the stored item; preserve the source/protected ESP and retain screenshots, raw responses and committed-generation verification.

One root commit and host fault tests establish a bounded transaction foundation. They do not establish a full POSIX transaction API, arbitrary physical power-loss certification, retention policy, encrypted multi-user Trash, network/external-volume Trash, unlimited history or finished Files workflows.

## Guest evidence and session Undo

The Source11 guest proof moves an actually open signed-fixture file, verifies that a retained descriptor mutates the moved inode, preserves a conflicting Restore destination, restores to an alternative name, reboots the same disposable store, and tests Purge cancellation and confirmation. Independently inspected CRC-valid private data/metadata pairs match the observed operations. The image, compiled-source manifest, helper binding and bytes outside the authorized132-sector journal region remain unchanged. Initial Home/frame/selected-row/focus harness assumptions are retained as failed observations rather than concealed.

Source12 adds bounded session-only Undo receipts. Undo Move restores the original data/name; Undo Restore recreates the exact Trash identity and original path. Cancel preserves an eligible receipt; successful use consumes it, and content/generation changes, Purge or session reboot invalidate it. The exact Source12 image (`1dbcad2f1dd4`, compiled193-file `e577af`) passed the actual two-boot `tools/trash_undo_smoke.py` gate:118create and119verify assertions, exact committed bytes/id, cancellation, one-shot replay rejection and a fresh eligible receipt invalidated by reboot. Protected bytes/image/source/helper binding remained unchanged. Its first wrapper attempt sent U while Terminal had focus; that failed harness observation is retained separately, and the successful retry explicitly opens Trash first. Host inverse/fault tests remain separate from guest evidence. This is not general editor/desktop Undo, unlimited history or cross-session recovery.
